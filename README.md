# cadastre_etl

Кадастровые объекты лотов банкротных торгов: сервис читает лоты, которые собирает
[trading_platform](https://github.com/geo-info/trading_platform) в MongoDB, находит в
них кадастровые номера, получает по каждому сведения и геометрию с кадастровой карты
НСПД (библиотека [pynspd](https://github.com/yazmolod/pynspd)) и складывает в PostGIS:
лоты, объекты с геометрией, связь лот ↔ объект.

Работает инкрементально: за прогон читает у каждой площадки только лоты, пришедшие
или изменившиеся после её прошлой проверки. Устройство и решения —
[спека](docs/specs/2026-09-29-cadastre-etl-design.md), план —
[docs/plans](docs/plans/2026-09-29-cadastre-etl.md).

## Быстрый старт

```bash
uv sync                                   # зависимости
docker compose up -d postgis              # PostGIS на 127.0.0.1:5432
uv run python -m cadastre_etl migrate     # схема
uv run python -m cadastre_etl run         # прогон всех площадок
```

Mongo — та, куда пишет trading_platform (по умолчанию `mongodb://localhost:27017`,
база `trading`). Своя Mongo для разработки: `docker compose --profile dev up -d mongo`.

**НСПД отвечает только на российские адреса.** С зарубежного (и из облачных CI)
каждый запрос получает 403 `BlockedIP`; тогда нужен `NSPD_PROXY`.

## Запуск

```bash
uv run python -m cadastre_etl run                 # все площадки, один прогон
uv run python -m cadastre_etl run bep seltim      # только эти
uv run python -m cadastre_etl run --loop          # прогон, пауза INTERVAL, снова
uv run python -m cadastre_etl run --full          # перечитать все лоты, а не только изменившиеся
uv run python -m cadastre_etl status              # etl_state таблицей
uv run python -m cadastre_etl sources             # коллекции Mongo и их состояние
uv run python -m cadastre_etl migrate             # только миграции (run делает их сам)
```

Площадки обрабатываются параллельно (не больше `SOURCE_CONCURRENCY`), упавшая не
мешает остальным. В конце — таблица:

```
площадка   лотов  номеров  из сети  из кэша  не найдено  ошибок  отложено  статус  время
bep          124       37       12       22           3       0         0  ok       41 с
utender        0        0        0        0           0       0         0  failed    0 с  ServerSelectionTimeoutError: …
(повторы)      0       15       15        0           0       0         0  ok        8 с
всего        124       52       27       22           3       0         0
```

- **лотов** — прочитано из Mongo (изменившиеся); **номеров** — уникальных у площадки;
- каждый номер — ровно в одной из колонок: **из сети**, **из кэша** (кэш pynspd или
  уже получен в этом прогоне для другой площадки), **не найдено**, **ошибок**,
  **отложено** (сработал предохранитель — НСПД не спрашивали);
- **(повторы)** — номера, оставшиеся с прошлых прогонов в `pending`/`error`.

Коды выхода `run`:

| код | когда |
|---|---|
| 0 | всё хорошо |
| 1 | площадка упала, не применились миграции или недоступна база |
| 2 | неверные аргументы или площадки нет в Mongo |
| 3 | площадки прошли, но НСПД недоступна (сработал предохранитель) |

В режиме `--loop` ошибка прогона цикл не останавливает; SIGTERM/SIGINT отменяют
текущий прогон (его состояние не сдвигается) и завершают процесс.

`--full` нужен, когда в `lots` добавились колонки (например, миграция `0002` с
типом торгов): обычный прогон читает только изменившиеся лоты, и у загруженных раньше
новые поля остались бы пустыми. Ответы НСПД при этом берутся из кэша, но лимит
частоты тратится — тысяча номеров займёт около 8 минут.

### Журнал: идёт или висит

Ход прогона пишется в stderr: куда подключились, сколько площадок, по каждой —
граница выборки, каждая пачка лотов и итог, а раз в 15 с — пульс:

```
INFO cadastre_etl.pipeline: PostGIS: подключение к localhost:5432/cadastre
INFO cadastre_etl.pipeline: Mongo: подключение к mongodb://localhost:27017, база trading
INFO cadastre_etl.pipeline: площадок: 32 (alfalot, arbbitlot, …), одновременно до 4
INFO cadastre_etl.pipeline: bep: начало, читаю лоты после начала (первый прогон)
INFO cadastre_etl.pipeline: bep: пачка из 500 лотов, с номерами 212; новых номеров 340 — спрашиваю НСПД
INFO cadastre_etl.pipeline: идёт прогон: площадок готово 3 из 32; НСПД — запросов 1210 (из кэша 400, неудачных 0), ждут ответа 318 номеров
INFO cadastre_etl.pipeline: bep: готово за 512 с — лотов 1843, номеров 977
```

Первый прогон по всем площадкам идёт долго: каждый номер — запрос в НСПД, не чаще
`NSPD_RATE` (2) в секунду, то есть тысяча номеров — около 8 минут. Растущее
«запросов» в пульсе значит, что работа идёт. `-v` (`python -m cadastre_etl -v run`)
включает подробный журнал, вплоть до каждого HTTP-запроса. Недоступные PostGIS или
Mongo дают ошибку через 10 с, а не молчание.

В Windows сервис сам запускает цикл событий, совместимый с асинхронным psycopg
(`SelectorEventLoop`): цикл по умолчанию (`ProactorEventLoop`) psycopg не поддерживает.

### Docker

```bash
docker compose up -d                      # PostGIS + сервис в режиме цикла
docker compose run --rm etl run bep       # разовый прогон в контейнере
docker compose --profile redis up -d      # плюс Redis для кэша (NSPD_CACHE=redis)
```

Сервис `etl` — в сети хоста: Mongo trading_platform (её compose публикует
`127.0.0.1:27017`) и PostGIS видны как `localhost`. Кэш НСПД — на томе `nspd-cache`.

## Настройки

Всё — в `src/cadastre_etl/conf.py` (pydantic-settings): окружение и `.env` в корне,
окружение приоритетнее. Длительности: секунды (`600`), ISO 8601 (`PT10M`) или
`90s`/`10m`/`2h`/`7d`.

| переменная | по умолчанию | смысл |
|---|---|---|
| `MONGO_URI` | `mongodb://localhost:27017` | Mongo trading_platform |
| `MONGO_DB` | `trading` | база |
| `POSTGRES_DSN` | `postgresql://etl:etl@localhost:5432/cadastre` | PostGIS |
| `OVERLAP` | `10m` | перекрытие окна выборки (см. «Состояние») |
| `INITIAL_SINCE` | — | первый прогон площадки — с этой даты (`ГГГГ-ММ-ДД`); без неё — все лоты |
| `SOURCE_CONCURRENCY` | `4` | площадок одновременно |
| `EXCLUDE_SOURCES` | — | коллекции, которые не площадки, через запятую |
| `BATCH_SIZE` | `500` | лотов в пачке записи |
| `INTERVAL` | `30m` | пауза между прогонами в `--loop` |
| `LOG_LEVEL` | `INFO` | журнал в stderr |
| `NSPD_TIMEOUT` | `30` | таймаут запроса, с |
| `NSPD_RATE` | `2` | запросов в секунду на процесс |
| `NSPD_CONCURRENCY` | `4` | одновременных запросов |
| `NSPD_RETRIES` | `3` | повторов номера в прогоне (таймаут, обрыв, 429, 5xx) |
| `NSPD_BREAKER` | `20` | неудачных запросов подряд до остановки запросов в прогоне |
| `NSPD_RETRY_LIMIT` | `1000` | номеров из очереди повторов за прогон |
| `NSPD_PROXY` | — | прокси к НСПД |
| `NSPD_CACHE` | `sqlite` | `sqlite` / `redis` / `none` |
| `NSPD_CACHE_PATH` | `.cache/nspd.sqlite` | файл SQLite-кэша |
| `NSPD_REDIS_URL` | `redis://localhost:6379/0` | Redis-кэш |
| `NSPD_CACHE_TTL` | `7d` | срок жизни ответа в кэше — и «найдено», и «не найдено» |

## Как устроено состояние

Таблица `etl_state` — строка на площадку (= коллекцию Mongo). Новая коллекция —
новая строка при первом прогоне.

1. Прогон площадки берёт её advisory-замок: второй экземпляр сервиса ту же площадку
   пропустит (`skipped`).
2. `run_started = now()` — **до** чтения Mongo.
3. Выбираются лоты, у которых `updated_at` **или** `detail_at` позже
   `checked_at − OVERLAP`. Оба поля: номер часто появляется только в `detail`,
   который trading_platform дописывает позже листинга, не трогая `updated_at`.
4. Пачками: номера → лоты, связи и заготовки объектов в PostGIS → НСПД → исходы.
5. Успех — `checked_at = run_started`. Ошибка — текст в `last_error`, `checked_at`
   прежний, следующий прогон повторит окно. Запись идемпотентна: повтор — не дубль.

**Почему перекрытие 10 минут.** Оно закрывает запись в Mongo во время чтения,
расхождение часов хостов и главное: `detail_at` в trading_platform — время
*запроса* страницы деталей, а не записи, и отстаёт от записи на длительность запроса
(до `HTTP_TIMEOUT` = 60 с и повторов). `OVERLAP` должен быть больше.

**Ошибки НСПД площадку не роняют.** Номер заводится заготовкой `pending` ещё до
запроса; ошибка оставляет его в очереди повторов, которая разбирается в начале
каждого прогона (первая ошибка — в следующем прогоне, дальше паузы растут до суток).

## Кэш НСПД

Своего кэша нет: повторы одного номера гасит встроенный кэш pynspd (Hishel 0.1).
Ответы 200 и 404 хранятся `NSPD_CACHE_TTL` независимо от заголовков сервера — то
есть «не найдено» тоже кэшируется и перепроверится только по истечении срока;
403/429/5xx не кэшируются. Внутри прогона номер запрашивается один раз, даже если
встретился на нескольких площадках. (Хранилище собирается сервисом и передаётся
в pynspd через `cache_storage`: `AsyncNspd(cache_sqlite_url=…, cache_ttl=…)` в
pynspd 1.1.15 бросает `ValueError`.)

## Схема БД

| таблица | что |
|---|---|
| `lots` | лоты с хотя бы одним номером или кварталом: ссылки, номер и тип торгов (`trade_id`, `trade_number`, `trade_type`, `auction_name`), номер лота, описание, статус, цена строкой и числом, сроки строкой (`bids_end`, `auction_date`) и датой (`bids_end_at`, `auction_at`), должник, организатор, победитель, `cad_quarters`, отметки времени Mongo |
| `cadastral_objects` | `cad_num` PK, `status`, вид (`kind`, `kind_label`), категория НСПД, ключевые поля (адрес, площадь, категория земель, ВРИ, кадастровая стоимость, статус в ЕГРН, дата постановки, квартал, форма собственности), `attrs jsonb`, `geom geometry(Geometry, 4326)` + GIST, `geom_approx` (точка геокодера), `fetched_at`, счётчик и текст ошибок |
| `lot_cadastral` | связь `(source, lot_id, cad_num)`, `found_in` — где в лоте нашёлся номер |
| `etl_state` | `checked_at` и итог последнего прогона площадки |
| `lot_objects` | представление: лот × объект × `geom` — слой для QGIS |

Исходы `cadastral_objects.status`: `pending` (ещё не спрашивали), `found` (есть
геометрия — контур или точка), `found_no_geom` (своих координат нет — помещения,
часть ЕЗП), `not_found`, `ambiguous` (несколько объектов с номером; кандидаты в
`attrs`), `error`. Ошибка ранее найденное не затирает. Хранится последняя версия
объекта; геометрия — в EPSG:4326 (НСПД отдаёт 3857, pynspd перепроецирует), тип —
Multi*.

Кварталы (`63:17:0519006` без номера объекта) хранятся ссылкой в
`lots.cad_quarters`, в НСПД не запрашиваются. Миграции — SQL-файлы в
`src/cadastre_etl/db/migrations/`, применённые — в `schema_migrations`.

## Разработка

```bash
docker compose --profile dev up -d mongo postgis
uv run pytest                     # офлайн-тесты; Mongo и PostGIS — из compose
uv run pytest -m live             # живые тесты НСПД (нужен российский адрес или NSPD_PROXY)
uv run pytest -m live --record    # и записать ответы в tests/fixtures/nspd/recorded/
uv run ruff check
uv run ruff format
```

Маркеры `mongo`/`postgres` ставятся сами по фикстурам теста: без сервиса — skip, с
`REQUIRE_MONGO=1`/`REQUIRE_POSTGRES=1` (так в CI) — ошибка. Ответы НСПД в
`tests/fixtures/nspd/` — синтетика по схемам pynspd (см. README там); настоящие
пишет `--record`.

```
src/cadastre_etl/
  conf.py              настройки
  extract.py           кадастровые номера и кварталы из лота
  mongo.py             площадки и выборка изменённых лотов
  nspd/client.py       запрос в НСПД поверх pynspd, кэш
  nspd/parse.py        ответ → исход, вид, ключевые поля, геометрия 4326
  nspd/resolver.py     дедуп в прогоне, лимиты, повторы, предохранитель
  db/                  пул, миграции, запись лотов/объектов/состояния
  pipeline.py          прогон площадок и очереди повторов
  report.py            таблицы
  __main__.py          CLI
```
